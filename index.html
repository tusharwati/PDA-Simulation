What is a pushdown automaton?

A PDA is a finite automaton with a stack. The stack gives it unbounded memory, but only last-in, first-out access. A DFA cannot check aⁿbⁿ because it cannot count arbitrarily high; a PDA pushes one symbol per a and pops one per b.

Formal definition

M = (Q, Σ, Γ, δ, q₀, Z₀, F)
δ ⊆ Q × (Σ∪{ε}) × (Γ∪{ε}) × Q × Γ*

A configuration is (state, remaining input, stack). A move reads an optional input symbol, pops an optional stack symbol, and pushes a string. This tool writes a transition as read, pop → push.

Acceptance

Final state: all input is consumed and the PDA is in a state of F. Empty stack: all input is consumed and the stack is empty (the initial stack holds Z₀ = Z, so some transition must pop it).

Nondeterminism

A string is accepted if any branch of the computation accepts. The configuration tree shows every branch the simulator explored, searched breadth-first. Deterministic and nondeterministic PDAs are not equivalent: palindromes wwᴿ need nondeterminism.

Relationships

PDA ≡ context-free grammar (every CFL has a PDA and vice versa). Compared with DFA/NFA, a PDA adds a stack and recognizes more (aⁿbⁿ). Compared with a Turing machine, it has a restricted stack instead of a freely rewritable tape, so it recognizes fewer languages (aⁿbⁿcⁿ is out of reach).

CFG → PDA (construction)

For S → aSb | ε: push S; if the top is a variable, replace it by a production body (ε-move); if the top is a terminal matching the input, pop it and consume; accept when the stack is empty. Try the “Grammar S→aSb|ε as PDA” example, which is this construction written out by hand. Automatic conversion of arbitrary grammars is not implemented here.
